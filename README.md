# 好理家在財務決策覺察檢測

本資料夾是「1 個入口檢測＋4 個延伸檢測」的靜態驗證版。入口先用 8 個生活選擇整理決策考量；使用者若想繼續，再選一個 6 題主題探索。結果描述本次作答線索，不是人格、能力、關係安全或完整財務評估。

目前狀態：`validation-ready`。題目、結果文字與工具銜接仍需認知訪談及小型試填；v11.7 已移除不會保存的結果回饋區塊，保留跨面向綜合摘要與三項工具建議，並已部署至夥伴測試網址 <https://familyfin-financial-habits-preview.vercel.app/>。

## 架構

- 入口：做金錢決定時，我通常先在意什麼？（8 題）
- 延伸一：我看得懂自己的錢嗎？（6 題）
- 延伸二：壓力來時我會怎麼用錢？（6 題）
- 延伸三：我和家人的金錢界線清楚嗎？（6 題）
- 延伸四：我的財務計畫卡在哪裡？（6 題）

三個靜態頁面共用一套資料驅動引擎：

- `index.html`：說明與 1＋4 架構
- `assessment.html?assessment=entry|clarity|pressure|family|plan`：共用作答頁
- `result.html?view=overview`：入口結果、五項進度與綜合分析共用的財務決策總覽
- `result.html?assessment=clarity|pressure|family|plan`：四個延伸主題的獨立結果頁
- `data.mjs`：題目、結果與工具資料
- `scoring.mjs`：三種計分策略
- `result-view.mjs`：結果摘要、小步驟與漸進式工具區
- `app.mjs`：頁面控制、選答、自動前進與一次性結果交接

## 操作規則

- 滑鼠或觸控選答後，保留約 380ms 選取狀態再前往下一題。
- 鍵盤選答後不自動換題，可按「下一題」。
- 未回答不能前進；上一題可回去修改。
- 進度顯示目前第幾題，不以已選答案數計算。
- 「我沒有遇過這個狀況」算完成，但不計分。
- 原始作答只在目前頁面記憶體中；完成時以一次性 `sessionStorage` 交給結果頁，讀取後立即刪除。
- 同一瀏覽分頁另保留最小結果摘要，供探索總覽顯示完成狀態、回看結果與重測；不含逐題答案、分數或會員資料，關閉分頁即清除。
- 重新整理、重新作答或重新進入作答頁都從空白開始。

## 結果原則

- 入口呈現主要、並列、次要或依情境改變的決策線索，不使用雷達圖或分數。
- 入口結果以白話描述作為主標，並以次層標籤呈現本次有依據的類型名稱；混合或資料不足時不勉強套用單一類型。
- 每份結果先顯示摘要，再以「做法／考量、這樣做的幫助、可以留意」三個等權節點呈現分析；並列與混合結果不會隱藏其他方向。
- 結果引用實際選過的情境與答案，不從平均數延伸心理側寫。
- 入口結果推薦一個延伸主題；只有主要方向並列且分流不同時，才顯示兩個等位入口。
- 延伸結果先提供一個本人可完成的約 10 分鐘小步驟；工具區預設展開，使用者仍可收合。
- 工具最多為 1 項主要工具與 2 項其他資源；作答資料不會自動帶入工具。
- 完成入口探索後直接進入「我的財務決策總覽」；入口摘要、圖像分析與重新測驗都在同一頁，不再另開入口結果頁或重複顯示入口卡片。
- 總覽保留五段進度，但卡片區只呈現四個延伸主題；四個主題可回看摘要與分析或重測。
- 延伸結果頁以「回到我的財務決策總覽」為主要動作；「重新測驗這個主題」為次要動作。
- 五項都完成後，顯示固定的 1＋4 決策地圖，以及整體輪廓、跨面向連動、可保留做法、留意處與下一步。五個角度沒有高低，也不合成總分或心理／財務診斷。
- 完成頁依入口主題順序與四個延伸結果，輪替取出三項不重複工具；資料不足時才補通用起點，且不把通用工具說成精準判定。

完整統計與計分規則見 [PARTNER-SCORING-GUIDE.md](./PARTNER-SCORING-GUIDE.md)。

## 協作與版本控管

- 本資料夾是問卷的獨立 Git 主程式；預設分支為 `main`。
- 每次修改都從 `main` 建立 Codex Worktree，不直接在 `main` 上開發。
- 夥伴完成本機預覽與測試後，可建立自己的分支與 Draft PR；由 Kevin 審查並決定是否合併。
- 合併到 `main` 不代表公開網址已更新。Vercel 連線與部署是另外的決策。
- 詳細的 Codex 操作方式見交接資料夾中的「夥伴快速操作卡」。
- Codex 的專案邊界、禁改項目與驗證指令見 [AGENTS.md](./AGENTS.md)。

## 內容來源

編輯來源為：

- `build_ivy_one_plus_four_report.py`：入口 8 題與 8 種考量
- `extension_assessment_content.py`：四個延伸檢測、結果與工具路徑
- `generate_assessment_data.py`：把編輯來源轉成瀏覽器使用的結構化 `data.mjs`

若內容來源有變更，可先執行產生器並人工檢視輸出；公開介面不得顯示 `option.value`、內部代碼或分數。

`data.mjs` 是瀏覽器執行時需要的生成檔，會納入版本控管，但不可直接手改。`publish-ready/` 是可重建的發佈副本，不是權威來源，也不納入 Git。
